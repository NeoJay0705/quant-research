# 研究就緒資料快取需求

## 1. 狀態與目標

需求名稱：**研究就緒資料快取**（research-data-cache）。

2026-11 使用者確認：每個新的策略研究都應能直接從研究開始，不必每次重做資料準備直到研究輸入（`ResearchData`）。需求經逐點確認，並經獨立審查（結論：修正後接受）；審查後新增或改寫的項目已由使用者確認。**已設計、實作並驗收**（使用說明見[研究就緒資料快取使用說明](research-data-cache-usage.md)）。

本需求不改變[機器人優先策略研究環境需求](robot-first-strategy-research-requirements.md)已確認的回測、成本及公司行動帳務規則，也不改變下載層。

## 2. 現況與量測事實

資料流：

```text
官方下載 → raw 快照（不可變）
        → records 表（第一次正規化：逐筆解析、未調價、帶品質旗標）
        → Dataset 層（唯讀、即時計算：分類、事件、調整價）
        → research.load_taiwan（轉成 Bar／CorporateAction）
        → ResearchData
```

`load_taiwan` 每次重讀 SQLite 並重算，沒有可重複使用的持久快取（Dataset 處理時僅使用暫時性的作業區）。

2026-11 以本機真實資料唯讀量測（日期 2018-01-02～2026-10-22；未提供分類證據 manifest；`/usr/bin/time` 的 RSS 以 GiB 計）：

| 範圍 | 標的數 | bars | 耗時 | 峰值記憶體 |
|---|---:|---:|---:|---:|
| TWSE 100 檔（未開 profiler） | 100 | 167,894 | 約 32 秒 | 0.74 GiB |
| TWSE 全部 4 位數代碼（cProfile 下） | 1,156 | 2,121,014 | 約 1,316 秒 | 11.0 GiB |
| TPEX 全部 4 位數代碼（cProfile 下） | 969 | 1,720,791 | 約 1,033 秒 | 8.9 GiB |

- 全量數字是在 cProfile 下取得，沒有未開 profiler 的全量量測；兩個「100 檔」的標的集合不同，不能由此推出 profiler 倍率或線性關係。
- 「4 位數代碼」只是量測用的過濾，量測未驗證各檔實際分類；量測也未提供分類證據，所以分類只來自代碼規則。
- 以全部代碼載入 TWSE 會失敗：目前轉換對每一檔（含非普通股）讀取事件，遇到事件明細不可用（例如 `2887F`、`2887G` 的 TWT49U 明細）即整次中止，每次約 8 分鐘後才發生。原因（未下載、來源缺漏或其他）未查證。
- TPEX 已存 48,372 個報價代碼（約 1,756 萬筆報價），遠多於 4 位數代碼，內容未查證。

調價現況（讀碼，`dataset/arithmetic.py`）：

- 每檔以載入範圍內第一筆報價為起點、累計倍率 1，其後依事件日累乘；調整價 = 原價 × 當日累計倍率。
- 每個事件倍率只由事件自己的欄位決定（`share_multiplier`，或面額變更的前價／參考價）。只有減資與面額變更等換股事件有倍率；現金股利／配股不調價。
- 調整價水準取決於連乘起點，同一天的調整價會隨載入起點不同；同一標的的價格變動比率不受影響。回測使用原價與事件帳務，不受此影響。
- 分類是逐筆報價判斷（輸入含各筆的名稱與市場別，理論上可隨日期不同）；分類規則只認 4 位數代碼，非 4 位數代碼一律為 `unknown`（`invalid_symbol_shape`）；只有該檔載入範圍內所有報價分類均為 `ordinary_evidence_supported` 或 `ordinary_rule_limited` 時才計算調整價。分類證據 manifest 為選用輸入；沒有證據時，普通股只能來自代碼規則。
- 2026-11 以本機資料、不提供證據，逐筆分類全部 4 位數代碼（TWSE 1,156 檔、TPEX 969 檔；其他代碼依規則必為 `unknown`）：**沒有任何標的出現混合分類**。逐檔結果：TWSE 1,139 檔 `ordinary_rule_limited`、11 檔 `excluded_non_ordinary`（00 開頭代碼）、6 檔 `unknown`（名稱或市場別可疑）；TPEX 968 檔 `ordinary_rule_limited`、1 檔 `unknown`。先前載入失敗的 `2887F`、`2887G` 不是 4 位數代碼，不在 RDC-02 範圍內。

## 3. 需求

| ID | 需求 | 接受方向 |
|---|---|---|
| RDC-01 | 新研究可直接載入研究就緒資料，不必每次從 records 重做轉換。讀出的研究輸入語意須與 `load_taiwan` 相同。 | `Bar`／`CorporateAction` 的數值、空值、品質旗標、分類及來源參照語意不變；**市場交易日曆（sessions）與 `load_taiwan` 同口徑**，不只是快取內 Bar 的日期；分類診斷與分類證據雜湊、受保護輸入目錄資訊須保留，使研究結果不會寫入快取或來源目錄。 |
| RDC-02 | 範圍為上市（TWSE）與上櫃（TPEX）中分類為 `ordinary_evidence_supported` 或 `ordinary_rule_limited` 的標的。涵蓋**快取涵蓋期間**內的全部已下載資料；涵蓋期間自建立時指定的起日起，不涵蓋該日以前的資料。 | 不預先以標的清單限制；不納入其他分類。保留前兩種分類差別，不宣稱完整普通股母集合或 PIT。分類證據為選用輸入，使用何種證據須記錄。判斷以**整檔標的**為單位（沿用 Dataset）：現有資料沒有混合分類的標的；若日後出現（含更新時新日期的分類改變），該檔整檔列為不可用並記錄原因，不保留合格日期。 |
| RDC-03 | 快取為衍生資料，與下載層分離，可刪除並可由現有 records 與分類證據重建。 | 不寫入、不 migration、不修改 raw／records／snapshots／分類證據；不下載、不啟用排程。快取位置在下載資料根目錄之外。 |
| RDC-04 | 快取內容為每個標的每日 Bar（原價、調整價、分類及來源參照）、公司行動事件，以及市場交易日曆。 | 原價與調整價並存；現金股利／配股不調價的現有語意不變；事件保留來源條件與日期欄位。 |
| RDC-05 | 無法轉換的標的略過，並在快取中記錄標的與原因；任何一次建立／更新指令不得留下部分結果。 | 單一標的轉換失敗不使整體失敗。研究者要求不可用標的時得到明確錯誤與原因，不得回傳空資料、補值或默默忽略；不屬 RDC-02 範圍的標的亦記錄原因。來源範圍不可用、儲存錯誤等指令層錯誤使整個指令失敗，不當作單一標的略過；失敗後快取內容與指令前相同。更新時既有標的因新日期出現轉換失敗或分類改變，該標的整檔轉為不可用（原已存資料不再可讀），以重建恢復；不保留可讀的舊前段。 |
| RDC-06 | 增量補建：只加入該市場已建立日期之後的新日期。 | 「已建立日期」以**每個市場**記錄；新出現的標的自其在新日期範圍內的首筆報價建立。既有日期的資料與調整價不變；新日期的調整價沿用現有規則：事件日期須晚於該檔起點且不晚於該報價日，每個事件只套用一次。驗收須含：事件落在無報價的日期、事件剛好在首筆新增報價當日、重複多次更新。 |
| RDC-07 | 指定起始日重建：可指定標的（或全部）與起始日，從該日重建到結尾。 | 該日之前保持不變，之後重新轉換。**在起始日以前的來源資料、事件及分類證據與上次建立時相同的條件下**，結果與從頭完整重建一致；若這些輸入已變動，使用者須選擇涵蓋最早受影響日期的起始日，否則不保證與完整重建一致。 |
| RDC-08 | 更新只由明確指令觸發，不自動偵測來源修訂。 | 不偵測舊日期被修訂、舊日期出現新事件或新版本 snapshot；這類情形由使用者以 RDC-07 處理，列為已知限制。 |
| RDC-09 | 調整價為累計調整：還原價 = 原價 × 歷史累計倍率，連乘起點固定為該檔快取中最早的報價（變更前為 1x，每次換股事件連乘該事件倍率）。 | 切片載入時調整價水準不再隨切片起點改變；同一標的的價格變動比率不變。歷史日期的還原價不因新增日期或新事件被改寫；最新還原價不保證等於市場價。日後補入更早資料會使該檔起點移動、水準可能改變，須以 RDC-07 從最早日期完整重建該檔，列為已知限制。此為對現有行為的已知變更，須在文件說明。 |
| RDC-10 | 來源參照僅作紀錄。 | 快取記錄所用來源 snapshot 識別以便追溯，不用於判定快取是否過期。 |
| RDC-11 | 研究者自行決定要讀哪些資料；除 RDC-02 的範圍外，不另行替研究者過濾。 | 可按市場、標的、日期選取；分類欄位保留供自行過濾。 |
| RDC-12 | 還原價是換股調整後的價格序列，用於同一標的的價格變動比率與相對量；絕對價格條件使用原價。 | 使用說明須明示：價格門檻、成交與持倉估值使用原價。現金股利與配股不納入倍率（含息還原不在本需求範圍）。 |
| RDC-13 | 讀取須揭露快取涵蓋範圍，不得把未建立的範圍當作「沒有報價」。 | 可查詢每個市場的涵蓋期間（起日、已建立日期）與各標的的可用／不可用狀態及原因。要求超出涵蓋期間的日期得到明確錯誤。明確指定的標的在所要求期間內沒有報價時得到明確錯誤（與 `load_taiwan` 相同）；未指定標的時，只納入在該期間內有報價的可用標的。 |

## 4. 後續決定（不屬於本次需求）

- 記憶體與檔案切分方式：待研究分析的存取方式確定後再決定。
- 快取檔案格式、具體 API 與指令名稱、儲存表示（例如整欄儲存調整價或只存倍率）：設計階段決定。
- 全部資料建立與讀取的耗時與記憶體：實作後以冒煙量測加比例推估取得（見§6）。
- 事件明細不可用的原因：不屬於本需求；需要時另行查證，不因此授權下載或回補。

## 5. 非目標

- 不改動下載層、raw、records 或 Dataset 的既有語意與分類規則；不改變調價倍率的來源與種類，不提供含息還原，也不提供讓最新價等於市價的往回調整。
- 不做自動過期偵測、背景更新或排程。
- 不處理其他市場、不混合跨市場；不接引擎或券商；不新增快取以外的分析功能；不改變回測、成本、公司行動帳務規則。
- 快取不是來源事實；缺資料不補值。

## 6. 驗收方向

- 以小範圍真實資料核對：快取讀出的 Bar／事件／交易日曆與現有 `load_taiwan` 對同一範圍的結果一致；調整價水準差異依 RDC-09，以起點相同的條件核對。
- 增量補建與指定起始日重建後，在 RDC-07 的條件下結果與從頭完整建立一致；邊界案例見 RDC-06。
- 無法轉換、範圍外分類、混合分類的標的被略過、有記錄原因，且要求該標的時得到明確錯誤。
- 指令失敗後快取與指令前相同。
- 建立與更新前後，下載資料根目錄的檔案 size 與 mtime 不變（SQLite 的 `-shm` 因唯讀連線可能變動，需另行註明）。
- 建立與讀取的耗時與記憶體，以多個資料量（N 筆）的冒煙量測取得，再依比例推估全部資料；須記錄各 N 的量測值與推估方式，並明示全量為推估而非實測（使用者 2026-11 決定：不設通過門檻，不要求全量實跑）。
