# Dataset 本機資料盤點與實測需求

## 1. 狀態與目標

需求名稱：**Dataset 本機資料盤點與實測**（dataset-local-validation）。使用者於 2026-10-30 確認本文件範圍，並同意使用預設台股資料根目錄 `~/.local/share/quant-research/taiwan/`。設計須另經確認，才開始實作與驗證。

使用者後續確認執行順序為：**先小範圍實測，再擴展到全量盤點**。先做選案例所需的局部查詢，以小範圍真實資料執行既有 Dataset 核心；實測經檢查接受後，再盤點指定根目錄內全部已保存的官方資料，提供可重跑工具與可核對證據。全量盤點不等於全量 Dataset 計算驗證；後者不在本次授權範圍。本需求不是全市場完整性認證，不恢復已刪除的 Dataset 發布、coverage、版本管理或公開 API。

沿用 [Dataset 需求](taiwan-quant-dataset-requirements.md)、[設計](taiwan-quant-dataset-design.md)及[使用界線](taiwan-quant-dataset-usage.md)的計算與資料安全邊界；本文件只新增內部盤點／實測能力，不改變既有官方報告語意。

## 2. 已確認功能與接受條件

| ID | 需求 | 接受條件 |
|---|---|---|
| DLV-01 | 小範圍實測接受後，唯讀全量盤點指定根目錄內既有 TWSE／TPEx 官方行情、事件摘要及必要明細。 | 提供資料的日期範圍與筆數；日期須說明意義，查詢／保存範圍不冒充行情或事件的實際日期。舊 FinMind 不混入官方統計。全量僅指已保存官方資料的盤點，不是全量 Dataset 計算驗證或全市場完整性認證。 |
| DLV-02 | 區分歷史保存量與最新任務版本可用資料。 | 歷史多版本可計入保存量，但不得將其誤稱有效行情／事件數；列出最新任務失敗、未完成或不可用的情況。不回退舊成功結果掩蓋最新失敗。 |
| DLV-03 | 先以必要的局部查詢選擇小範圍真實案例，不以前置全量盤點作為條件。 | 明確限定案例的市場、代碼、日期區間及採用來源參照；涵蓋一般行情，以及局部資料中可用的減資／面額變更／分配等案例。沒有適合案例時明示缺項，不自動擴大搜尋、下載補齊或用人工資料冒充真實驗證。 |
| DLV-04 | 執行實際 Dataset 內部流程。 | 呼叫既有讀取→分類→事件整理→順序調價流程，不以另一個示範計算器替代。保留原始行情與計算結果供比較。 |
| DLV-05 | 比較預期行為與實際結果。 | 核對原始 OHLC／量／金額未改；減資／面額倍率依原需求在生效當日及後續套用且不回改；股利／配股／退還款保留但不調價；缺值、分類、來源參照保留。無可用真實案例的項目不得標為通過。 |
| DLV-06 | 提供可重跑內部工具及必要測試。 | 工具重跑可重新產生盤點與驗證證據；不是穩定公開 Python API，不增加正式 Dataset CLI／格式或匯出產品。 |
| DLV-07 | 提交本次摘要與驗證紀錄。 | 說明來源／dataset、範圍、筆數定義、案例及採用參照；逐項記錄預期值、實際值與通過／失敗／缺少可驗證資料。測試成功不能代替真實案例核對。 |

## 3. 預期輸出內容

```text
資料現況
  來源／dataset
  保存資料日期與筆數
  最新任務版本狀態與可用資料
  適合或不適合實測的案例與原因

真實案例
  市場／代碼／日期區間
  實際採用的行情、事件摘要／明細參照
  原始值 → 預期倍率與調整值 → 實際值
  分類、缺值、分配、量與金額、來源參照核對
  結論：通過／失敗／缺少可驗證資料
```

此為驗證證據內容，不定義正式 Dataset 輸出格式或永久保存策略。

## 4. 非目標與操作授權

- 只讀指定 production DB／raw／可信本機分類證據；不下載、不回補、不啟用排程。
- 不修改 production 資料、schema、索引、驗證標記或歷史檔案，不清理 raw、DB、WAL／SHM 或分類證據。
- 允許 SQLite 正常管理 live WAL／SHM；不以 `immutable=1` 忽略 WAL。唯讀不等同作業系統完全沒有 sidecar／access-time 變動。
- 不全量轉換或全量逐筆驗證 Dataset、不建立發布 bundle、不決定公開使用介面與匯出格式、不計算含息總報酬或執行回測；本次全量工作只限實測接受後的資料盤點。
- 若發現既有核心錯誤，先回報具體證據與必要修正範圍，不自行擴大修改。
- 實際盤點及驗證產物不得污染 production 根目錄；不把大型 raw／DB／完整本機證據加入版控。

## 5. 階段門檻

1. 本需求已確認並歸檔。
2. 主助手提出最小實作設計、非功能性假設與執行流程；待使用者確認後歸檔設計。
3. 主助手分段委派實作／測試，逐段檢查證據。先接受局部查詢選定的案例資料，再執行真實計算核對；小範圍實測經接受後，才執行全量盤點，不因工具具備全量能力就提前執行。
4. 有失敗或證據不足時明示；缺項不冒充通過，未解決的實測失敗須先回報，不能依賴失敗結果繼續擴展。不將部分通過推廣為完整歷史、全量計算已驗證或整體可回測。
