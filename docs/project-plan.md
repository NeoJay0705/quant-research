# 專案計畫

## 需求完整性

長期研究範圍涵蓋台股、美股與加密貨幣。

初始化需求已足夠，可以建立 Python 3.13、uv、可安裝的 typed src layout 套件、鎖定依賴、品質檢查、文件與 CI。
此階段不選擇首個實作市場或資料商，也不加入金融套件、資料、ETL、回測或 CLI。

後續實作需求仍不足。資料範圍、供應商、授權、時間語意、研究方法、產物與保留政策都需要先決策，不能用程式預設值代替需求確認。

## 使用情境

研究者需要一套可重現的跨市場研究流程，讓資料來源、取得時間、轉換、回測假設與研究結果可追溯，並能檢查未來資訊偏誤與生存者偏誤。
本次初始化只提供套件骨架、安裝版本煙霧測試與開發檢查；尚未實作上述研究流程或金融功能。

## 階段與門檻

依序進行各階段。未滿足前一階段的決策與驗收門檻，不進入下一階段。

1. **初始化**：建立 Python／uv 專案、鎖定依賴、可安裝套件、品質檢查、文件與 CI。此階段已具備足夠需求。
2. **資料來源與契約定義**：先決定供應商、授權、商品範圍、頻率、時區、交易日曆、時間點可得性及價格欄位語意，再定義資料契約。沒有明確決策前不開始接資料。
3. **資料補齊與 ETL**：在來源及契約確認後，先選一個市場、一種頻率作為垂直切片。市場與頻率尚未預選。驗收須包含可追溯來源、轉換及資料品質檢查。
4. **回測與偏誤驗證**：在資料時間語意明確後，定義並驗證避免未來資訊偏誤及生存者偏誤的方法，再決定成本、滑價與資金費率等假設。
5. **研究產物與量化指標**：先定義研究產物、指標、可重現所需資訊及驗收方式，再實作產生與檢查流程。
6. **經核准的保存／清理**：先訂保留政策，驗證備份與重建性，提供 dry-run，並取得明確批准後才能執行清理。

## 取捨與資料可追溯性

- 優先建立小而可安裝、可測試的基礎，不先加入未決定的市場或金融依賴。
- 未來資料記錄應能追溯資料來源、取得時間、轉換版本及內容雜湊等資訊。這是需求方向，不是本次已定義或實作的 schema。
- 原始資料及中間產物不得自動刪除。只保留摘要不足以重建研究，也不能取代來源資料、轉換依據與必要的執行資訊。
- `data/` 與 `artifacts/` 的 Git 忽略設定不構成備份、保留或刪除政策。
- 本次不啟動服務、不取得 API key，也不抓取市場資料。

## 未決策問題

- 資料供應商、授權條款與可否再散布。
- 標的範圍、退市標的與歷史成分資料。
- 資料頻率、時區、交易日曆與休市處理。
- 公司行動、調整價格及還原價語意。
- Crypto venue、商品範圍與 24x7 時間切分方式。
- 各欄位在當時可得的時間點及資料延遲。
- 回測成本、滑價、資金費率及其他交易假設。
- 研究產物與量化指標的內容、格式與驗收標準。
- 資料及產物的存取控制、備份、保留與核准清理政策。
- 「產出資料量化」一詞的確切語意尚待確認。不得將它解讀為已決定採用有損壓縮。

## 錯誤處理與清理原則

遇到來源不可用、契約不符、資料缺漏或驗證失敗時，流程應明確報錯並保留足以追查的資訊，不得靜默略過、猜測語意或用未確認的資料替代。涉及需求選擇時，先停止並取得決策。

原始資料和中間產物不得自動刪除。未來清理前必須決定保留政策、驗證備份與重建性、提供 dry-run，並取得明確批准。不得把 Git 忽略或保存摘要當成資料備份或可重建性的證明。
