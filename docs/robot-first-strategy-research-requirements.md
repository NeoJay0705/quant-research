# 機器人優先策略研究環境需求

## 1. 狀態與目標

需求名稱：**機器人優先策略研究環境**（robot-first-strategy-research）。

2026-10-30 使用者確認研究優先的方向，並補充主要研究人員是機器人，擅長無UI操作。Notebook不是必要入口；若順帶提供manager檢視介面會增加困難，可以不提供。

使用者進一步明確：機器人先了解提供哪些功能及如何使用，再依自己的研究想法自行操作。環境提供可發現、可理解、可組合的能力，不替機器人規定研究想法或強制固定工作流。首版資料為TWSE／TPEx普通股日線，但不應把所有研究能力綁定台股；不同市場分別研究，共通概念可共用，資料特有語意另行明確處理。此方向不代表首版須交付其他市場資料或支援所有市場交易規則。

**需求與修訂後設計已確認；首版Python研究功能、少量真實研究及獨立安裝已分段接受。** 使用者以「ok keep going」同意§4.4整體首版範圍。既有回測基準及缺少實際入帳／新股可交易日期時採事件生效日替代的研究口徑均已確認。成本數值為每次研究需明示的輸入，不在需求階段替研究者拍定；首版採標準函式庫、無UI的Python介面及已確認模擬假設；交付與接受狀態見設計§11。

核心目標：讓研究者容易編寫、檢查、回測、調整、驗證想法與尋找特徵。大部分研究會被淘汰；只有少數成果轉為實際策略。不得為未來實際運行共用性，先增加每個研究的負擔。

## 2. 已確認的研究流程

```text
提出想法
  → 取得研究資料
  → 自訂／觀察特徵
  → 檢查特徵是否有訊息
  → 形成交易假設並回測
  → 分析結果與失敗原因
  → 調整、比較、重現
```

研究可在任一步結束，不強迫每個特徵實驗都成為完整策略。上述為可能的研究循環，不是必須依序執行的工作流；機器人可自行選擇、組合及反覆呼叫功能。探索程式不必一開始符合實際運行的生命週期；值得保留的邏輯再整理為可重用模組。

5. 這些規則是取得可解讀回測結果的必要條件，不是探索特徵之前必須填完的整套交易設定；也不要求使用者在需求討論中先決定所有參數。

### 4.3 已確認的事件日替代口徑（2026-10-30）

使用者提出缺少實際入帳日期時以事件發生日處理，並在查核資料與說明偏差後明確同意以下規則。此為首版研究簡化模型，不必僅因缺少實際日期就阻擋研究回測。

**RSR-19：入帳／新股可用日期選取。**

1. 資料有可靠且語意明確的實際入帳／新股可交易日期時，使用該日期。
2. 沒有該日期時，以已知event effective_date作模擬現金入帳／新增股數可用日；不是下載日、申報日或任意第一筆行情日。
3. 分配只適用有權獲得分配的事件前持倉，不能把事件日新買股數也計入本次分配。當日事件帳務與委託處理先後須在設計中明確定義。
4. 原來源中未知的實際日期維持未知，不回填或改寫production；模擬日期、採用依據及替代假設另記錄，可供機器人查核。
5. 結果明確揭露事件日入帳假設，以及可能提早再投資／提早出售新增股數的偏差。這是該研究模型下的績效，不宣稱重現券商實際入帳帳務。
6. 日期替代不補足其他必要金融條件：分配金額、股數比例或事件生效日若缺失，仍依RSR-18明確處理，不捏造資料。

接受條件：分別以有實際日期、缺日期替代、事件日新買不獲本次分配、來源未知日期不被改寫，以及報告揭露假設的案例核對。此為後續實作驗收要求，目前尚未實作或執行相關回測測試。

### 4.5 已確認的純面額變更換股語意（2026-10-31）

**RSR-20：純面額變更可由面額推算股數比例，不必要求額外直接換股率欄位。** 使用者指出純面額變更本身不涉及退還款，可依變更前後面額計算；主助手依此修正原先只有直接share_multiplier才允許持倉換股的過窄限制。

若舊面額為p_old、新面額為p_new，兩者有限且大於零，則m=p_old/p_new，換發後股數=q*m，純面額變更本身不增減現金。例如10元改2.5元，每原股換4股。現金股利、減資退還款等若另有事件條件，仍依其獨立帳務處理，不因純面額規則而被抹去。

直接股數比例或可靠的前後面額均可提供換股條件；同時存在時須檢查一致性。面額比不是股票市場價格比，不從價格比猜整數。若現有來源缺面額及直接比例，仍是必要來源條件待補足，不捏造面額，也不因此自動取得新下載授權。

### 4.6 已確認的結果私有權限（2026-10-31）

**RSR-21：新建研究結果預設只允許擁有者存取。** 使用者於公開提交前同意最小安全修正：在POSIX系統以0700建立最終結果目錄，以0600排他建立其內新檔（含COMPLETE與暫存marker）；仍遵守更嚴格的呼叫者umask。不得修改程序全域umask，也不得chmod既有父目錄、既有檔案或來源；既有拒覆寫、來源保護及原子完成標記語意不變。一般umask000／022／077均須驗證目錄0700、所有新檔0600；失敗留下的部分產物亦保持私有。此保護不是跨平台ACL認證、root／同UID隔離或任意Python程式沙箱。

## 5. 既有能力與衝突界線

依[專案需求](project-requirements.md)、[Dataset使用界線](taiwan-quant-dataset-usage.md)與[本機驗證結果](dataset-local-validation-usage.md)：

- 現有Dataset為內部離線計算核心，不是已完成的研究／回測環境。正式使用介面仍待本需求反推；不自動恢復已刪除的bundle、coverage、公開API或匯出格式。
- 小範圍計算實測與全部已保存官方資料盤點已完成，但不是全量普通股計算驗證、完整普通股歷史或PIT認證。
- Dataset股利／配股／退還款保留但不調價，不提供完整投資帳務或含息報酬。回測不得直接把調整價漲跌幅當成已處理全部分配的投資績效。
- 分類與歷史股池限制須揭露，不將今日名冊當作歷史普通股母集合。先前15筆不可用明細對應特別股，不等於普通股資料缺漏；也不能藉此推論普通股資料全數可用。
- 既有production DB／raw／可信分類證據維持原安全界線。新功能或研究不因此獲得下載、回補、排程啟用、來源修改或刪除授權。
